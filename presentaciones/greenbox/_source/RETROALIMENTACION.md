# Notas para futuras revisiones

1. Definir primero el programa y la unidad de análisis. Separar la red empresarial de beneficiarios del proyecto evitó duplicar impacto.
2. La cadena compartida ordena las interacciones: relacionar actor, etapa, control y evidencia reduce textos repetidos.
3. Conservar niveles medios en la matriz evita inventar bajos para completar cuadrantes. Hacer explícita la lógica de filtros permite pruebas útiles.
4. Los KPIs se explican mejor como tres dimensiones con dos metas; mostrar seis fichas extensas y todas las fórmulas a la vez haría más pesada la exposición.
5. Preparar un PDF editorial desde el contenido, no desde el scroll. Revisar todos los estados esenciales, tablas de actores y escenarios antes de cerrar.
6. Encajar al 100% y lectura ampliada son intenciones distintas. El encuadre automático no debe cancelar el zoom manual al navegar.
7. Reutilizar activos existentes sin repetir la composición aceleró el rediseño y mantuvo contexto visual real.
8. Empaquetar datos, pruebas, licencias y generador PDF junto al código mantiene futuras modificaciones reproducibles.

9. Confirmar el perímetro de stakeholders con el trabajo base antes de cambiar etiquetas. La unidad de análisis puede ser la cadena completa, no solo la sociedad jurídica.
10. No usar microtipografía decorativa en una exposición: ampliar etiquetas, notas y SVG, y después redistribuir para recuperar el encuadre. Una prueba sin recortes no garantiza legibilidad.
